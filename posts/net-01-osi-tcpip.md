그누가 네트워크를 기초부터 다시 잡고 자격증까지 가 보겠대서, 첫 편으로 OSI 7계층과 TCP/IP를 정리해 봤어요. 외울 게 많아 보이지만 "데이터가 내려가며 헤더를 입고, 올라가며 벗는다"는 한 문장만 잡으면 나머지는 거기에 붙어요.

## 왜 계층으로 나눌까요

통신은 한 덩어리로 보면 너무 큰 문제예요. 전선에 전기 신호를 싣는 일, 옆 장비에 전달하는 일, 지구 반대편까지 길을 찾는 일, 빠진 데이터를 다시 보내는 일, 웹 페이지를 해석하는 일이 전부 섞여 있거든요.

그래서 층으로 잘라요. 얻는 건 두 가지예요.

- 문제 분리: 각 층은 자기 일만 해요. 웹 페이지가 안 열릴 때 "케이블인가, IP인가, 포트인가, 애플리케이션인가"를 아래부터 차례로 좁혀 갈 수 있어요.
- 교체 가능: 층 사이 약속만 지키면 한 층을 통째로 바꿔도 돼요. 유선 랜을 와이파이로 바꿔도 브라우저는 고칠 필요가 없어요. 1~2계층만 바뀌었고 그 위는 그대로니까요.

## OSI 7계층, 아래에서 위로

OSI는 국제표준화기구(ISO)가 만든 참조 모델이고 7계층이에요. 실제 인터넷이 이대로 구현된 건 아니지만, 장비와 장애를 설명하는 공용어로 쓰여요.

- 1계층 물리: 비트를 전기, 빛, 전파 신호로 바꿔 보내요. 케이블, 허브, 리피터가 여기예요.
- 2계층 데이터링크: 같은 네트워크 안의 옆 장비까지 전달해요. MAC 주소를 쓰고 오류를 검출해요. 이더넷, 스위치.
- 3계층 네트워크: 서로 다른 네트워크를 건너 목적지까지 길을 찾아요. IP 주소와 라우팅. 라우터.
- 4계층 전송: 프로그램과 프로그램 사이를 이어요. 포트 번호로 프로그램을 구분해요. TCP는 순서와 재전송을 보장하고 UDP는 보장 없이 가볍게 보내요.
- 5계층 세션: 대화의 시작, 유지, 종료를 관리해요.
- 6계층 표현: 데이터의 형식을 맞춰요. 인코딩, 압축, 암호화.
- 7계층 응용: 우리가 쓰는 프로그램이 직접 닿는 층이에요. HTTP, DNS, SSH.

순서는 아래부터 "물데네전세표응"으로 외우면 편해요.

## TCP/IP 4계층과 맞춰 보기

실제 인터넷은 TCP/IP 모델로 돌아가요. 이 글은 4계층 모델(RFC 1122의 구분) 기준이에요. 교재에 따라 맨 아래를 물리와 데이터링크로 쪼갠 5계층으로 설명하기도 하니, 문제를 풀 때는 "몇 계층 모델 기준인지"부터 확인하세요.

- 응용 계층 = OSI 5, 6, 7계층
- 전송 계층 = OSI 4계층
- 인터넷 계층 = OSI 3계층
- 네트워크 접근 계층 = OSI 1, 2계층

OSI 위쪽 세 층이 하나로 합쳐진 게 핵심이에요. 그래서 TLS처럼 "5계층이냐 6계층이냐"가 애매한 프로토콜이 생겨요. TLS는 TCP 위, HTTP 아래에서 동작한다고 기억하는 편이 정확해요.

## 캡슐화: 헤더를 입고 벗기

보내는 쪽에서 데이터는 위에서 아래로 내려가며, 층마다 자기 헤더를 앞에 붙여요. 이걸 캡슐화라고 해요.

받는 쪽은 반대로 올라가며 헤더를 하나씩 떼요. 역캡슐화예요.

![캡슐화: 데이터가 내려가며 헤더를 하나씩 입는 모습](img/net1-encap.png)

층마다 데이터 덩어리를 부르는 이름이 달라요.

- 4계층: 세그먼트(TCP). UDP는 데이터그램이라고 불러요.
- 3계층: 패킷
- 2계층: 프레임
- 1계층: 비트

숫자로 보면 더 잘 잡혀요. 이더넷 프레임이 실을 수 있는 페이로드는 최대 1,500바이트이고 이 값이 MTU예요. 여기서 IP 헤더 최소 20바이트, TCP 헤더 최소 20바이트를 빼면 TCP가 한 번에 실을 수 있는 데이터는 1,460바이트예요.

반대로 바깥에는 이더넷 헤더 14바이트(목적지 MAC 6, 출발지 MAC 6, 타입 2)가 앞에, 오류 검출용 FCS 4바이트가 뒤에 붙어서 프레임 전체는 최대 1,518바이트가 돼요(VLAN 태그가 없을 때). 2계층만 머리와 꼬리를 둘 다 붙인다는 점도 같이 기억해 두세요.

## 스위치는 2계층, 라우터는 3계층까지

장비가 "몇 계층 장비"라는 말은 헤더를 어디까지 열어 보느냐는 뜻이에요.

- 허브(1계층): 헤더를 안 봐요. 들어온 신호를 모든 포트로 그대로 내보내요.
- 스위치(2계층): 이더넷 헤더의 목적지 MAC 주소를 보고 해당 포트로만 보내요.
- 라우터(3계층): 이더넷 헤더를 벗기고 IP 헤더의 목적지 IP를 봐요. 라우팅 테이블에서 다음 경로를 고른 뒤, 새 이더넷 헤더를 입혀 내보내요.

여기서 중요한 사실이 하나 나와요. 라우터를 지날 때마다 MAC 주소는 구간마다 바뀌지만, IP 주소는 출발지부터 목적지까지 유지돼요(NAT가 없다면요).

그리고 IP 헤더의 TTL은 라우터를 하나 지날 때마다 1씩 줄어요. 참고로 라우팅까지 하는 L3 스위치도 있어서, 시험에서 그냥 "스위치"라고 하면 2계층 스위치로 보면 돼요.

## 웹 요청 한 번 따라가기

브라우저 주소창에 https://example.com 을 넣고 엔터를 눌렀을 때예요. TCP 위에서 도는 HTTPS(HTTP/1.1, HTTP/2) 기준이에요.

1. DNS 조회(7계층): 이름을 IP 주소로 바꿔요. 보통 UDP 53번 포트로 질의해요.
2. TCP 3-way 핸드셰이크(4계층): 서버 443번 포트로 SYN을 보내고, SYN+ACK를 받고, ACK로 답해요. 세 번 오가면 연결이 열려요.
3. TLS 핸드셰이크: 서버 인증서를 확인하고 암호화에 쓸 키를 합의해요.
4. HTTP 요청과 응답(7계층): GET / 요청이 암호화된 채 나가고 응답이 돌아와요.

이 모든 단계의 데이터가 매번 TCP 헤더, IP 헤더, 이더넷 헤더를 입고 내려가요. 처음 프레임의 목적지 MAC은 서버가 아니라 우리 집 공유기(기본 게이트웨이)예요. 서버는 다른 네트워크에 있으니 일단 라우터에게 맡기는 거예요.

게이트웨이의 MAC은 ARP로 알아내요. 이후 라우터들이 IP 헤더를 보며 넘기고(집 공유기의 NAT 로 출발지 IP 는 바뀔 수 있어요), 서버가 헤더를 차례로 벗겨 HTTP 요청을 꺼내요.

## 보안 엔지니어 눈으로 보면

보안 장비도 "어느 헤더까지 보느냐"로 나뉘어요.

- 방화벽, 보안 그룹(SG): 3~4계층. 출발지와 목적지 IP, 프로토콜, 포트로 허용과 차단을 정해요. "443번 포트는 열고 22번은 특정 IP만" 같은 규칙이에요.
- WAF: 7계층. HTTP 요청의 URL, 헤더, 본문을 읽고 SQL 인젝션이나 XSS 같은 패턴을 막아요.

그래서 SG로 443번을 열어 두면, 그 포트로 들어오는 악성 HTTP 요청은 SG가 걸러 주지 못해요. SG는 포트까지만 보고 내용은 안 보니까요.

그 내용을 보는 게 WAF의 자리예요. 층이 다르면 막을 수 있는 공격도 달라요 ^^7

## 시험에서는 이렇게 나와요

세 시험 모두 이 주제는 짝짓기 문제가 기본이에요.

- 계층과 데이터 단위 짝짓기: 프레임은 2계층, 패킷은 3계층, 세그먼트는 4계층
- 계층과 장비 짝짓기: 허브와 리피터 1계층, 스위치와 브리지 2계층, 라우터 3계층
- 계층과 역할 짝짓기: 암호화와 압축은 표현 계층, 경로 설정은 네트워크 계층
- OSI와 TCP/IP 대응: OSI 5~7계층이 TCP/IP 응용 계층 하나로 묶인다는 점

정확한 출제 범위와 비중은 각 시험 공식 안내에서 확인하세요.

## 요약

- 계층으로 나누는 이유는 문제 분리와 교체 가능성이에요.
- OSI는 7계층, TCP/IP는 4계층(이 글 기준)이고 OSI 5~7이 응용 하나로 합쳐져요.
- 내려가며 헤더를 입는 게 캡슐화, 올라가며 벗는 게 역캡슐화예요. 단위는 세그먼트, 패킷, 프레임, 비트 순이에요.
- 스위치는 MAC(2계층), 라우터는 IP(3계층)까지 봐요. MAC은 구간마다 바뀌고 IP는 끝까지 가요.
- 방화벽과 SG는 3~4계층, WAF는 7계층이에요.

다음 편에서는 3계층의 주소인 IP 주소와 서브넷 계산을 손으로 해 볼게요. 이더넷과 스위치는 4편에서 다뤄요.

## 확인 문제

1. OSI 7계층에서 3계층의 데이터 단위는 무엇일까요?
   1) 비트 2) 프레임 3) 패킷 4) 세그먼트

2. TCP/IP 4계층 모델의 응용 계층에 대응하는 OSI 계층을 모두 고른 것은?
   1) 7계층만 2) 6, 7계층 3) 5, 6, 7계층 4) 4, 5, 6, 7계층

3. 라우터를 하나 통과할 때 일어나는 일로 옳은 것은? (NAT 없음)
   1) 출발지 IP 주소가 라우터의 IP로 바뀐다
   2) 이더넷 헤더의 MAC 주소가 새로 쓰이고 IP 주소는 유지된다
   3) MAC 주소와 IP 주소가 모두 유지된다
   4) TCP 포트 번호가 바뀐다

4. 이더넷 MTU가 1,500바이트이고 IP 헤더와 TCP 헤더가 각각 20바이트일 때, TCP 세그먼트 하나에 실을 수 있는 데이터의 최대 크기는?
   1) 1,440바이트 2) 1,460바이트 3) 1,480바이트 4) 1,500바이트

5. HTTP 요청 본문에 담긴 SQL 인젝션 패턴을 검사해 차단하는 데 가장 알맞은 것은?
   1) 2계층 스위치 2) 라우터 3) 보안 그룹(SG) 4) WAF

## 정답과 해설

1. 정답 3). 3계층(네트워크)의 단위는 패킷이에요. 프레임은 2계층, 세그먼트는 4계층이에요.
2. 정답 3). TCP/IP의 응용 계층은 OSI의 세션, 표현, 응용 세 층을 하나로 묶은 거예요.
3. 정답 2). 라우터는 이더넷 헤더를 벗기고 다음 구간용으로 새로 입혀요. IP 주소는 NAT가 없으면 끝까지 그대로예요.
4. 정답 2). 1,500 - 20 - 20 = 1,460바이트예요. 이더넷 헤더 14바이트와 FCS 4바이트는 MTU 바깥이라 계산에 넣지 않아요.
5. 정답 4). 요청 본문은 7계층 내용이에요. SG는 IP와 포트(3~4계층)까지만 보고, HTTP 내용을 읽는 건 WAF예요.
