그누가 "콘솔 오른쪽 위에서 서울을 고르긴 하는데, 그게 실제로 어디에 뭘 고르는 건지는 잘 모르겠다"고 해서 2편은 리전과 가용 영역으로 정리해 봤어요. 1편이 "누가 쓰는가"였다면 오늘은 "어디에 두는가"예요.

## 왜 알아야 하나

클라우드도 결국 어딘가의 건물 안 서버예요. 건물 하나에 전부 넣으면 정전이나 화재 한 번에 서비스가 통째로 멈춰요. 그래서 AWS 는 인프라를 여러 단계로 나눠 놓았고, 우리는 자원을 만들 때마다 "어느 단계에, 몇 군데에 둘지"를 골라야 해요. SAA 의 복원력 문제는 거의 다 이 선택을 묻는 문제예요.

## 개념: 리전, AZ, 엣지 로케이션

- **리전(Region)**: 지리적으로 떨어진 독립 구역이에요. 서울은 `ap-northeast-2`, 도쿄는 `ap-northeast-1` 처럼 코드가 있어요. 리전끼리는 기본적으로 격리돼 있어서, 서울에 만든 자원이 도쿄에 저절로 복제되지 않아요.
- **가용 영역(Availability Zone, AZ)**: 리전 안의 격리된 구역이에요. AZ 하나는 **하나 이상의 데이터센터**로 이루어져요. AZ 끼리는 전원, 냉각, 네트워크가 따로 있고 물리적으로 떨어져 있지만, 저지연 전용 회선으로 묶여 있어서 한 네트워크처럼 쓸 수 있어요.
- **엣지 로케이션**: 리전 밖, 이용자와 가까운 도시에 흩어진 거점이에요. CloudFront 가 콘텐츠를 캐시해 두고 Route 53 이 DNS 응답을 하는 자리예요. 서버를 직접 올리는 곳이 아니에요.

![리전 안에 AZ 4개가 있고 리전 밖에 엣지 로케이션이 흩어져 있는 계층 그림](img/aws-02-region-az-1.png)

정의와 전체 지도는 [AWS 글로벌 인프라 페이지](https://aws.amazon.com/about-aws/global-infrastructure/regions_az/)에서 볼 수 있어요.

## 숫자로 보기: 서울 리전

[AWS 리전 문서](https://docs.aws.amazon.com/global-infrastructure/latest/regions/aws-regions.html)(2026-11-23 확인) 기준으로 서울 리전은 **AZ 4개**이고 따로 활성화할 필요가 없어요. 같은 문서에서 버지니아 북부(us-east-1)는 6개, 오하이오(us-east-2)는 3개예요. 캘리포니아 북부(us-west-1)는 새 계정에 AZ 가 2개만 보인다는 주석이 붙어 있어요. "모든 리전은 AZ 가 3개"라고 외우면 틀려요.

전체 리전 수는 공식 페이지마다 달라요. 2026-11-23 에 조회했을 때 위 리전 문서는 "현재 34개 리전"이라고 쓰고, [글로벌 인프라 페이지](https://aws.amazon.com/about-aws/global-infrastructure/regions_az/)는 "39개 지리적 리전, 124개 AZ"라고 써요. 리전 문서의 목록에는 GovCloud, 중국, European Sovereign Cloud 가 빠져 있다는 것까지만 확인했어요. 개수는 외우지 말고 링크에서 그때그때 확인하는 게 맞아요.

## AZ 이름은 계정마다 다르다

여기가 오늘의 함정이에요. `ap-northeast-2a` 같은 **AZ 이름**은 계정마다 다른 물리 AZ 에 연결될 수 있어요. 내 계정의 2a 와 옆 계정의 2a 가 같은 건물이라는 보장이 없어요. 모두가 a 만 골라서 한쪽으로 몰리는 걸 막기 위한 장치예요.

물리 위치를 가리키는 고정 값은 **AZ ID** 예요. 서울은 `apne2-az1` 같은 모양이고, 이 값은 어느 계정에서 봐도 같은 AZ 를 뜻해요. 여러 계정이 "같은 AZ 에 두자" 또는 "다른 AZ 에 두자"고 맞출 때는 이름이 아니라 AZ ID 로 이야기해야 해요. 확인은 이렇게 해요.

```
aws ec2 describe-availability-zones --region ap-northeast-2 \
  --query "AvailabilityZones[].[ZoneName,ZoneId]" --output table
```

자세한 설명은 [AZ ID 문서](https://docs.aws.amazon.com/ram/latest/userguide/working-with-az-ids.html)에 있어요.

## 리전 고르는 기준 4가지

1. **지연**: 이용자와 가까운 리전일수록 응답이 빨라요. 한국 이용자가 대상이면 서울이 기본이에요.
2. **데이터 주권과 규제**: 데이터가 특정 국가 안에 있어야 한다는 법적 요건이 있으면 그게 1순위예요.
3. **서비스 제공 여부**: 새 서비스와 기능은 모든 리전에 동시에 나오지 않아요. 쓰려는 기능이 그 리전에 있는지 먼저 봐요.
4. **가격**: 같은 서비스도 리전마다 요율이 달라요. 가격 페이지가 리전별 표로 되어 있어요. 예를 들어 [VPC 가격 페이지](https://aws.amazon.com/vpc/pricing/)가 예시로 보여 주는 오하이오의 NAT 게이트웨이는 시간당 0.045달러예요(2026-11-23 조회). 한도와 가격은 바뀌니 링크에서 리전을 직접 골라 확인하세요.

앞의 세 가지는 리전 문서 첫머리에 그대로 적혀 있어요. 시험에서는 "규제 요건이 있다"는 문장이 나오면 지연이나 가격보다 규제가 먼저예요.

## opt-in 리전

리전 문서 기준으로 **2019-03-20 이후에 생긴 리전은 쓰기 전에 계정에서 활성화**해야 해요. 이걸 opt-in 리전이라고 불러요. 서울, 도쿄, 버지니아 북부 같은 예전 리전은 기본 활성이고, 2026-11-23 문서에는 기본 활성 17개와 opt-in 17개가 적혀 있어요. 상태는 `aws account get-region-opt-status` 로 볼 수 있어요. 안 쓰는 리전은 꺼 두는 게 기본값이라는 점은 보안 쪽에서도 반가운 이야기예요 ^^7

## 최신 리전 소식

같은 리전 문서(2026-11-23 확인)의 opt-in 목록에 멕시코 중부(mx-central-1), 타이베이(ap-east-2), 태국(ap-southeast-7), 뉴질랜드(ap-southeast-6)가 올라와 있어요. 글로벌 인프라 페이지는 사우디아라비아와 칠레 리전을 "발표됨"으로 적고 있어요. 오픈 날짜와 그 뒤 소식은 [AWS What's New](https://aws.amazon.com/new/)에서 확인하세요.

리전과 AZ 말고도 Local Zones(대도시 근처로 뻗은 확장 구역), Wavelength(통신사 5G 망 안), Outposts(내 전산실에 들여놓는 AWS 장비)가 있어요. 이번 편에서는 이름만 알아 두고, 정의와 지원 범위는 [Local Zones](https://aws.amazon.com/about-aws/global-infrastructure/localzones/), [Wavelength](https://aws.amazon.com/wavelength/), [Outposts](https://aws.amazon.com/outposts/) 공식 페이지에서 확인하세요.

## 서비스마다 범위가 다르다

자원을 만들 때 무엇을 고르게 하는지 보면 범위가 보여요.

| 범위 | 만들 때 고르는 것 | 예 | 장애 대비 |
|---|---|---|---|
| 글로벌 | 없음 | IAM, Route 53, CloudFront | AWS 가 맡음 |
| 리전 | 리전 | S3, DynamoDB | 리전 안 여러 AZ 에 AWS 가 분산 |
| AZ | 리전 + AZ | EC2 인스턴스, EBS 볼륨, 서브넷 | 내가 여러 AZ 에 나눠야 함 |

![글로벌 서비스 안에 리전 서비스, 그 안에 AZ 서비스가 들어 있는 범위 그림](img/aws-02-region-az-2.png)

기억할 연결 고리 두 개만 짚을게요. 서브넷 하나는 AZ 하나에만 속해요. 그리고 EBS 볼륨은 같은 AZ 의 EC2 인스턴스에만 붙일 수 있어요. 그래서 AZ a 의 인스턴스가 죽었다고 그 볼륨을 AZ b 의 인스턴스에 바로 꽂을 수는 없어요.

## 다중 AZ 와 다중 리전

| | 다중 AZ | 다중 리전 |
|---|---|---|
| 막는 장애 | 데이터센터나 AZ 하나의 장애 | 리전 전체 장애, 광역 재해 |
| 목적 | 고가용성(평소의 기본 설계) | 재해 복구, 글로벌 이용자 지연 단축 |
| 복제 | AZ 간 저지연이라 동기 복제가 쉬움 | 거리가 멀어 보통 비동기 복제 |
| 복잡도와 비용 | 낮음 | 높음(자원이 두 벌, 리전 간 전송료) |

예를 들어 가상의 서비스 example-app 을 서울에 올린다면, 서브넷을 AZ 2개 이상에 만들고 EC2 를 양쪽에 나눈 뒤 로드밸런서를 앞에 두는 게 출발점이에요. AZ 하나가 통째로 멈춰도 나머지가 받아 줘요. 다중 리전은 "서울 리전 전체가 멈춰도 몇 분 안에 살아나야 한다" 같은 요구가 있을 때 꺼내는 카드예요. 재해 복구 전략 네 가지(백업 및 복원, 파일럿 라이트, 웜 스탠바이, 다중 사이트 액티브-액티브)는 [AWS 재해 복구 백서](https://docs.aws.amazon.com/whitepapers/latest/disaster-recovery-workloads-on-aws/disaster-recovery-options-in-the-cloud.html)에 정리돼 있고, 뒤로 갈수록 복구는 빠르고 비용은 커져요.

비용 쪽(도메인4)에서 기억할 점은 AZ 를 넘거나 리전을 넘는 데이터 전송에는 요금이 붙을 수 있다는 거예요. 요율은 [EC2 온디맨드 가격 페이지](https://aws.amazon.com/ec2/pricing/on-demand/)의 데이터 전송 항목에서 확인하세요.

## 시험에서는 이렇게 나와요

- "고가용성", "AZ 장애에도 계속 동작"이 보이면 **다중 AZ** 가 답이에요. 다중 리전 보기는 대개 과한 설계라서 오답이에요.
- "리전 전체 장애", "재해 복구", "다른 대륙 이용자"가 보이면 **다중 리전**이에요.
- "가장 비용 효율적으로"가 붙으면 요구를 채우는 가장 작은 범위를 골라요.
- "규제상 데이터가 국내에 있어야 한다"가 나오면 리전 선택이 먼저 고정돼요.

## 요약

- 리전 안에 AZ, AZ 안에 데이터센터가 있어요. 엣지 로케이션은 리전 밖에서 이용자 가까이 있어요.
- 서울 리전은 AZ 4개예요(2026-11-23 리전 문서 기준).
- AZ 이름은 계정마다 다르게 연결될 수 있고, AZ ID 가 고정 값이에요.
- 리전은 지연, 규제, 서비스 제공 여부, 가격으로 골라요.
- 다중 AZ 는 고가용성의 기본, 다중 리전은 재해 복구용이에요.

## 확인 문제

**1.** 2026-11-23 AWS 리전 문서 기준으로 서울 리전(ap-northeast-2)의 AZ 개수는?
① 2개 ② 3개 ③ 4개 ④ 6개

**2.** 계정 A 와 계정 B 가 자원을 반드시 같은 물리 AZ 에 두려고 해요. 무엇을 기준으로 맞춰야 할까요?
① AZ 이름(ap-northeast-2a) ② AZ ID(apne2-az1) ③ 리전 코드 ④ 서브넷 이름

**3.** 다음 중 리전을 고르지 않고 쓰는 글로벌 서비스는?
① EBS ② 서브넷 ③ DynamoDB ④ IAM

**4.** 서울 리전에서 EC2 로 운영하는 웹 서비스가 AZ 하나의 장애에도 계속 동작해야 해요. 가장 비용 효율적인 설계는?
① 같은 AZ 에 인스턴스를 2대 둔다 ② 여러 AZ 에 인스턴스를 나누고 로드밸런서를 앞에 둔다 ③ 서울과 도쿄에 똑같은 환경을 두 벌 운영한다 ④ 인스턴스 크기를 2배로 키운다

**5.** 다음 중 쓰기 전에 계정에서 활성화(opt-in)해야 하는 리전은?
① 서울(ap-northeast-2) ② 버지니아 북부(us-east-1) ③ 태국(ap-southeast-7) ④ 아일랜드(eu-west-1)

## 정답과 해설

1. **③** 리전 문서에 서울은 AZ 4개, opt-in 불필요로 적혀 있어요. 6개는 us-east-1 이에요.
2. **②** AZ 이름은 계정마다 다른 물리 AZ 에 연결될 수 있어요. AZ ID 는 모든 계정에서 같은 AZ 를 가리켜요.
3. **④** IAM 은 글로벌이에요. DynamoDB 는 리전 범위, EBS 와 서브넷은 AZ 범위예요.
4. **②** AZ 장애는 다중 AZ 로 막아요. ①과 ④는 그 AZ 가 멈추면 같이 멈추고, ③은 요구보다 과해서 비용이 커요.
5. **③** 2019-03-20 이후에 생긴 리전은 활성화가 필요해요. 나머지 셋은 기본 활성 리전이에요.
