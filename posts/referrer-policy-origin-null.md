## 문제: 테스트 92개는 통과했는데 크롬 로그인은 전부 400

그누가 로그인 화면을 배포하고 크롬으로 접속하니 비밀번호 입력, 인증 코드 입력, 등록 세 가지 POST가 모두 400으로 막혔어요. 화면에는 "페이지가 만료됐어요"만 나왔어요. 자동 테스트 92개는 모두 초록불이었어요.

## 원인: no-referrer 가 같은 사이트 POST 의 Origin 도 null 로 만듦

로그인 화면에는 두 가지가 들어 있었어요.

```
Referrer-Policy: no-referrer
```

그리고 서버에는 CSRF 방어로 `Origin` 헤더가 우리 사이트인지 확인하는 코드가 있었어요.

`Origin` 도 `Referer` 처럼 요청이 어디서 왔는지 알려 주는 정보예요. 그래서 리퍼러 정책이 `no-referrer` 이면 브라우저는 `Origin` 도 숨겨서 값을 `null` 로 보내요. 외부로 나가는 요청만이 아니라 같은 사이트 안의 폼 제출도 마찬가지예요. 서버는 `null` 을 우리 사이트가 아니라고 판단해 정상 요청을 전부 막았어요.

테스트가 못 잡은 이유도 같은 곳에 있어요. 테스트 클라이언트는 `Origin` 헤더를 아예 보내지 않아요. 서버의 검사를 건드리지 않고 통과한 거예요.

## 해결: same-origin 으로 변경

```
Referrer-Policy: same-origin
```

같은 사이트 안에서는 `Origin` 과 `Referer` 가 정상으로 가요. 다른 사이트로 나갈 때는 `Referer` 가 가지 않아요. 원래 목적이었던 주소 노출 방지는 그대로예요.

## 결과: 400 이 사라지고 로그인이 복구

| | 수정 전 | 수정 후 |
|---|---|---|
| 로그인 관련 POST 3종 | 전부 400 | 정상 |
| 자동 테스트 | 92개 통과 | 92개 통과 |
| 실제 브라우저 | 사용 불가 | 사용 가능 |

자동 테스트 결과가 수정 전후로 같아요. 이 문제는 테스트로는 보이지 않았다는 뜻이에요. ( ˘ω˘ )

## 정리

1. `Origin` 이나 `Referer` 로 CSRF를 막는다면 같은 페이지에 `no-referrer` 를 걸지 마세요. `same-origin` 이면 충분해요.
2. 테스트 클라이언트는 브라우저가 보내는 헤더를 흉내 내지 못해요. 로그인 같은 핵심 경로는 헤드리스 크롬으로 폼 제출까지 한 번은 직접 돌려 보세요.
3. 보안 헤더는 서버 코드가 그 값을 어떻게 읽는지와 같이 확인해야 해요.
