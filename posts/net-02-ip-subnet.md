연재: 네트워크 기초부터 자격증까지 2편 / 시험 연결: 네트워크관리사 2급, 정보통신기사, CCNA(IP Connectivity, IP Addressing)

그누가 "/26 이면 호스트가 몇 개야?" 같은 질문만 나오면 계산기부터 찾게 된대서, 손으로 푸는 순서를 정리해 봤어요. 서브넷 계산은 세 시험에 모두 나오고, 시험장에는 계산기가 없거나 쓸 시간이 없어요. 방법은 한 가지라서 한 번 익히면 계속 써먹을 수 있어요.

## 왜 필요한가

IP 주소는 3계층(네트워크 계층)의 주소예요. 라우터는 주소 전체가 아니라 "어느 네트워크인가"만 보고 길을 정해요.

그래서 주소 하나를 네트워크 부분과 호스트 부분으로 나누는 기준이 있어야 하고, 그 기준이 서브넷 마스크예요. 방화벽 규칙이나 보안 그룹에 대역을 적을 때 쓰는 /24, /32 가 바로 이 표기예요.

## IPv4 는 32비트

IPv4 주소는 32비트예요. 8비트씩 4덩어리(옥텟)로 끊고, 각 덩어리를 십진수로 바꿔 점으로 이은 것이 점 십진 표기예요. 8비트가 나타내는 값은 0부터 255까지라서 옥텟에 256 이상은 올 수 없어요.

이진 변환은 자리값 8개만 외우면 돼요.

| 자리값 | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
|---|---|---|---|---|---|---|---|---|
| 37 | 0 | 0 | 1 | 0 | 0 | 1 | 0 | 1 |

큰 자리값부터 뺄 수 있으면 1, 없으면 0 을 써요. 37 은 32 를 빼면 5, 4 를 빼면 1, 1 을 빼면 0 이라서 32 + 4 + 1, 곧 00100101 이에요.

192.168.10.37 전체를 바꿔 볼게요.

- 192 = 128 + 64 → 11000000
- 168 = 128 + 32 + 8 → 10101000
- 10 = 8 + 2 → 00001010
- 37 = 32 + 4 + 1 → 00100101

## 서브넷 마스크와 CIDR

서브넷 마스크는 왼쪽부터 1이 연속으로 이어지는 32비트 값이에요. 1이 덮는 자리가 네트워크 부분, 0인 자리가 호스트 부분이에요.

CIDR 표기는 1의 개수를 슬래시 뒤에 적어요. /24 는 1이 24개니까 255.255.255.0 이에요.

마스크 옥텟에 올 수 있는 값은 9개뿐이에요. 0, 128, 192, 224, 240, 248, 252, 254, 255. 1이 하나 늘 때마다 128, 64, 32 순서로 더해진 값이에요.

## 세 가지 숫자 구하기

호스트 비트 수를 n 이라고 하면 이렇게 돼요.

- 네트워크 주소: 호스트 비트를 전부 0 으로
- 브로드캐스트 주소: 호스트 비트를 전부 1 로
- 사용 가능 호스트 수: 2^n - 2 (위 두 주소는 기기에 줄 수 없어서 빼요)

/24 는 n = 8 이니까 2^8 - 2 = 254개, /26 은 n = 6 이니까 2^6 - 2 = 62개예요.

손계산은 블록 크기로 해요. 마스크에서 255 도 0 도 아닌 옥텟을 찾아 256 에서 빼면 블록 크기예요.

네트워크 주소는 그 옥텟에서 블록 크기의 배수로만 시작해요. (/8, /16, /24 처럼 옥텟 경계에 딱 맞으면 그런 옥텟이 없으니 마스크가 255 인 앞부분이 네트워크 주소 그대로예요.)

## 실전 1: 192.168.10.0/24 를 4개로 나누기

1. 4개가 필요하니 2^2 = 4, 호스트 비트 2개를 빌려요. 24 + 2 = /26.
2. /26 마스크의 넷째 옥텟은 128 + 64 = 192. 마스크는 255.255.255.192.
3. 블록 크기 = 256 - 192 = 64.
4. 네트워크 주소는 0, 64, 128, 192.
5. 브로드캐스트는 다음 블록 시작에서 1 을 뺀 63, 127, 191, 255.
6. 남은 호스트 비트 6개, 서브넷마다 2^6 - 2 = 62개.

![192.168.10.0/24 를 /26 네 개로 나눈 블록 그림과 서브넷별 주소 범위 표](img/net-02-ip-subnet-1.png)

192.168.10.37 은 0 과 64 사이니까 첫 번째 서브넷(192.168.10.0/26) 소속이에요.

## 실전 2: 10.0.0.0/22 의 범위

1. /22 는 셋째 옥텟에 1이 6개. 128 + 64 + 32 + 16 + 8 + 4 = 252. 마스크는 255.255.252.0.
2. 블록 크기 = 256 - 252 = 4. 이번에는 셋째 옥텟에서 4씩 뛰어요.
3. 네트워크 주소 10.0.0.0, 다음 네트워크는 10.0.4.0.
4. 브로드캐스트는 그 직전인 10.0.3.255.
5. 사용 가능 범위는 10.0.0.1 부터 10.0.3.254.
6. 호스트 비트 32 - 22 = 10개, 2^10 - 2 = 1,022개.

10.0.1.255 와 10.0.2.0 이 평범한 호스트 주소라는 점이 함정이에요. 끝자리가 255 나 0 이라고 무조건 브로드캐스트나 네트워크 주소가 아니에요.

## 사설 IP 와 특수 주소

RFC 1918 사설 대역 3개는 통째로 외워요. 인터넷에서 라우팅되지 않아서 밖으로 나갈 때는 NAT 가 필요해요(뒤 편에서 다뤄요).

| 대역 | 범위 |
|---|---|
| 10.0.0.0/8 | 10.0.0.0 ~ 10.255.255.255 |
| 172.16.0.0/12 | 172.16.0.0 ~ 172.31.255.255 |
| 192.168.0.0/16 | 192.168.0.0 ~ 192.168.255.255 |

172.16.0.0/12 가 172.31 에서 끝나는 것이 단골 문제예요. 172.32.0.1 은 공인 IP 예요.

- 127.0.0.0/8: 루프백. 자기 자신을 가리켜요(대표 127.0.0.1).
- 169.254.0.0/16: 링크 로컬. DHCP 서버에서 주소를 못 받으면 PC 가 스스로 잡는 주소(APIPA)예요.
- 0.0.0.0: 주소가 아직 정해지지 않았다는 뜻. 0.0.0.0/0 으로 쓰면 "모든 주소"(기본 경로)예요.

## 클래스풀 A/B/C

CIDR 이전에는 첫 옥텟만 보고 마스크를 정했어요. 지금 장비는 CIDR 로 동작하지만 국내 시험에는 여전히 나와요.

| 클래스 | 첫 옥텟 | 기본 마스크 | 호스트 수 |
|---|---|---|---|
| A | 1 ~ 126 | /8 | 16,777,214 |
| B | 128 ~ 191 | /16 | 65,534 |
| C | 192 ~ 223 | /24 | 254 |

127 은 루프백이라 A 에서 빠지고, 224 ~ 239 는 D(멀티캐스트), 240 ~ 255 는 E(예약)예요.

## IPv6 맛보기

IPv4 주소는 2^32, 약 43억 개라서 부족해요. IPv6 는 128비트이고, 16비트씩 8묶음을 16진수로 써서 콜론으로 이어요.

묶음 앞쪽 0 은 생략할 수 있고, 0 만 있는 묶음이 연속되면 한 번만 :: 로 줄여요. 2001:0db8:0000:0000:0000:0000:0000:0001 은 2001:db8::1 이 돼요.

## 시험에서는 이렇게 나와요

- 네트워크관리사 2급: 클래스 구분, 기본 마스크, 서브넷 개수와 호스트 수
- 정보통신기사: 마스크가 주어졌을 때 네트워크 주소와 브로드캐스트 주소
- CCNA: 주소가 어느 서브넷 소속인지, 필요한 호스트 수에 맞는 프리픽스 고르기

## 요약과 예고

- 마스크의 1 은 네트워크, 0 은 호스트. /숫자 는 1 의 개수
- 블록 크기 = 256 - 마스크 옥텟. 네트워크 주소는 블록 크기의 배수
- 호스트 수 = 2^n - 2
- 사설 대역은 10/8, 172.16/12, 192.168/16

AWS VPC 는 CIDR 을 /16 부터 /28 까지만 허용하고 서브넷마다 IP 5개를 예약해요. 그래서 위 공식의 "- 2" 가 AWS 에서는 "- 5" 로 바뀌는데, 이유는 AWS 3편(VPC 설계)에서 다룰게요. 오늘 문제 5개를 계산기 없이 풀면 준비 끝이에요 (•̀ᴗ•́)و

## 확인 문제

**1. 십진수 168 을 8비트 이진수로 바꾼 것은?**
① 10100100 ② 10101000 ③ 10011000 ④ 11001000

**2. 192.168.1.130/27 이 속한 서브넷의 네트워크 주소와 브로드캐스트 주소는?**
① 192.168.1.128, 192.168.1.159 ② 192.168.1.128, 192.168.1.191 ③ 192.168.1.96, 192.168.1.127 ④ 192.168.1.130, 192.168.1.161

**3. 172.16.45.200/20 이 속한 네트워크 주소와 사용 가능 호스트 수는?**
① 172.16.32.0, 4,094개 ② 172.16.40.0, 2,046개 ③ 172.16.45.0, 254개 ④ 172.16.32.0, 4,096개

**4. 다음 중 RFC 1918 사설 IP 가 아닌 것은?**
① 10.200.3.4 ② 172.31.255.1 ③ 172.32.0.1 ④ 192.168.100.1

**5. PC 가 DHCP 서버에서 주소를 받지 못했을 때 스스로 설정하는 대역은?**
① 127.0.0.0/8 ② 169.254.0.0/16 ③ 0.0.0.0/8 ④ 224.0.0.0/4

## 정답과 해설

1. ② 168 = 128 + 32 + 8 이라서 10101000 이에요.
2. ① /27 의 넷째 옥텟 마스크는 224, 블록 크기는 256 - 224 = 32. 배수 0, 32, 64, 96, 128, 160 중 130 은 128 블록이고, 브로드캐스트는 160 - 1 = 159 예요.
3. ① /20 의 셋째 옥텟 마스크는 240, 블록 크기 16. 45 는 32 와 48 사이라 172.16.32.0. 호스트 비트 12개, 2^12 - 2 = 4,094개. ④ 는 2 를 빼지 않은 함정이에요.
4. ③ 172.16.0.0/12 는 172.31.255.255 에서 끝나요. 172.32 부터는 공인 IP 예요.
5. ② 169.254.0.0/16 링크 로컬(APIPA)이에요. 127/8 은 루프백, 224/4 는 멀티캐스트예요.
