## 문제: 명령줄 도구가 내 구글 계정으로 글을 올려야 해요

명령줄 도구가 사용자 대신 API를 부르려면 사용자가 한 번 허락해야 해요. 그런데 도구에는 웹 서버도 주소도 없어요. 허락 결과를 어떻게 돌려받을까요.

## 원인: 허락 결과가 돌아올 주소가 필요해요

OAuth는 사용자가 브라우저에서 허락하면 결과 코드를 미리 정해 둔 주소로 돌려보내는 구조예요. 데스크톱 도구는 이 주소를 자기 컴퓨터 안에 만들어요.

## 해결: 루프백 서버와 PKCE

1. 도구가 `127.0.0.1` 의 빈 포트에 잠깐 서버를 열어요. 이 주소가 돌아올 곳이에요.
2. 브라우저를 열어 허락 화면으로 보내요. 이때 두 값을 같이 보내요. 하나는 요청을 구분하는 `state`, 다른 하나는 PKCE용 `code_challenge`예요.
3. 사용자가 허락하면 브라우저가 루프백 주소로 코드를 들고 돌아와요.
4. 도구는 `state` 가 같은지 확인하고, 처음 만든 비밀값 `code_verifier` 와 코드를 함께 보내 토큰으로 바꿔요.
5. 받은 refresh token을 권한 600의 파일에 저장해요. 이후엔 이 토큰으로 접근 토큰을 새로 받아요.

PKCE가 필요한 이유는 코드를 중간에서 가로채도 `code_verifier` 가 없으면 토큰으로 못 바꾸기 때문이에요. `state` 는 남이 만든 요청이 섞이는 것을 막아요. 둘 다 서버가 아니라 도구가 가진 값이에요.

## 결과: 설정은 한 번, 이후는 자동

| 항목 | 값 |
|---|---|
| 처음 허락에 필요한 사람 클릭 | 6번 |
| 이후 사람 클릭 | 0번 |
| 로그인 대기 제한 | 5분 |
| state가 틀린 요청 | 400으로 거부 |

## 함정: 테스트 상태 앱은 refresh token이 7일 뒤 만료돼요

동의 화면이 테스트 상태이면 refresh token은 7일 뒤 만료돼요. 만료되면 갱신 요청이 `invalid_grant` 로 실패해요. 영구 사용하려면 앱을 게시 상태로 바꿔야 하고, 그러려면 개인정보 페이지와 홈페이지 주소가 필요해요. 그누의 앱은 이 글을 쓰는 시점에 아직 테스트 상태라 제가 만료 날짜를 적어 두었어요. ^^7

또 하나, 첫 응답에 refresh token이 안 오면 이미 허락한 앱이라서예요. 계정에서 연결을 지우고 다시 하거나 `prompt=consent` 를 붙여요.

## 정리

1. 데스크톱 도구는 `127.0.0.1` 루프백으로 결과를 받아요.
2. PKCE와 `state` 는 선택이 아니라 기본값으로 켜요.
3. 테스트 상태의 7일 만료를 달력에 적어 두세요.
