연재: 네트워크 기초부터 자격증까지 3편 / 시험 연결: 네트워크관리사 2급(라우팅 프로토콜, ARP), 정보통신기사(라우팅), CCNA(IP Connectivity)

그누가 "서브넷은 알겠는데, 패킷이 다른 네트워크로 어떻게 넘어가는지는 아직 그림이 안 그려진다"고 해서 3편은 라우팅으로 정리해 봤어요. 2편에서 배운 서브넷 계산이 오늘 바로 쓰여요.

## 왜 라우팅이 필요한가

같은 서브넷 안에서는 스위치만 있어도 통신이 돼요. 하지만 192.168.0.0/24 에 있는 PC 가 203.0.113.5 같은 바깥 주소로 보내려면 네트워크와 네트워크를 이어 주는 장비가 필요해요. 그게 라우터(3계층 장비)예요.

라우터가 하는 일은 단순해요. 패킷이 들어오면 **목적지 IP** 를 꺼내서 자기 **라우팅 테이블**과 비교하고, 맞는 줄에 적힌 방향으로 내보내요.

끝까지 가는 길을 다 아는 게 아니라 "다음 한 칸"만 정해요. 이 한 칸을 홉(hop)이라고 불러요.

## 라우팅 테이블 읽는 법

테이블 한 줄은 네 가지로 읽으면 돼요.

| 항목 | 뜻 | 예 |
|---|---|---|
| 목적지 | 어느 네트워크로 가는 길인가 | 10.1.0.0/16 |
| 넥스트 홉 | 다음에 넘겨줄 라우터의 IP | 10.1.255.1 |
| 인터페이스 | 어느 포트로 내보내나 | eth2 |
| 메트릭 | 같은 목적지 길이 여럿일 때 비용. 작을수록 좋음 | 10 |

## 최장 일치: 가장 구체적인 줄이 이긴다

목적지에 맞는 줄이 여러 개면 프리픽스가 가장 긴 줄을 골라요. 이걸 최장 일치(longest prefix match)라고 해요. 테이블에 10.0.0.0/8, 10.1.0.0/16, 0.0.0.0/0 세 줄이 있다고 해 볼게요.

1. **10.1.2.3**: 세 줄 모두 맞아요. 길이가 16, 8, 0 이니 **10.1.0.0/16** 을 타요.
2. **10.2.3.4**: 앞 16비트가 10.2 라서 /16 은 탈락이에요. 남은 것 중 긴 **10.0.0.0/8** 을 타요.
3. **8.8.8.8**: 10 으로 시작하지 않으니 **0.0.0.0/0** 만 남아요.

![라우팅 테이블에서 10.1.2.3 이 최장 일치로 10.1.0.0/16 을 고르는 예시](img/net-03-routing-1.png)

0.0.0.0/0 은 0비트만 맞으면 되니 모든 주소가 맞아요. 그래서 "달리 갈 곳이 없을 때 가는 길", 즉 기본 경로(default route)가 돼요. PC 에 설정하는 **기본 게이트웨이**가 바로 이 기본 경로의 넥스트 홉이에요. PC 는 목적지가 자기 서브넷 밖이면 무조건 기본 게이트웨이에게 넘겨요.

## 경로는 어디서 생기나

- **직접 연결(connected)**: 라우터 인터페이스에 IP 를 주면 그 서브넷이 자동으로 올라와요.
- **정적(static)**: 관리자가 손으로 적어요.
- **동적(dynamic)**: 라우터끼리 라우팅 프로토콜로 경로를 주고받아요.

정적은 단순하고 장비 부담이 없지만 회선이 끊겨도 스스로 우회하지 못해요. 동적은 장애가 나면 알아서 다른 길을 찾지만 설정과 자원이 더 들어요. 그래서 작은 망이나 기본 경로는 정적, 라우터가 많은 망은 동적을 써요.

## 동적 라우팅 프로토콜 세 가지

| 구분 | RIP | OSPF | BGP |
|---|---|---|---|
| 방식 | 거리 벡터 | 링크 상태 | 경로 벡터 |
| 쓰는 곳 | AS 내부(IGP) | AS 내부(IGP) | AS 사이(EGP) |
| 길 고르는 기준 | 홉 수(최대 15, 16은 도달 불가) | 비용(대역폭 기반) | AS 경로 등 속성 |
| 특징 | 이웃에게 자기 표를 주기적으로(30초) 전달 | 망 전체 지도를 만들고 SPF(다익스트라)로 계산 | TCP 179번 포트, 인터넷의 뼈대 |

AS 는 한 기관이 관리하는 네트워크 묶음이에요. 거리 벡터는 "이웃이 알려 준 거리"만 믿고, 링크 상태는 모두가 같은 지도를 갖고 각자 계산한다는 차이만 잡아도 문제의 절반은 풀려요.

같은 목적지를 여러 출처가 알려 주면 어느 쪽을 믿을까요? 여기에 쓰는 값이 관리 거리(AD)예요.

작을수록 믿어요. **아래 숫자는 Cisco 장비 기준**이고 제조사마다 달라요.

| 출처 | AD (Cisco 기준) |
|---|---|
| 직접 연결 | 0 |
| 정적 | 1 |
| eBGP | 20 |
| OSPF | 110 |
| RIP | 120 |

순서를 정리하면, 같은 프리픽스에 후보가 여럿이면 AD 로 출처를 고르고, 같은 프로토콜 안에서는 메트릭으로 골라 테이블에 올려요. 패킷을 보낼 때는 그 테이블에서 최장 일치로 찾아요.

## TTL 과 traceroute

경로가 꼬여서 패킷이 빙빙 돌면 큰일이에요. 그래서 IP 헤더에 TTL 이 있어요. 라우터를 하나 지날 때마다 1씩 줄고, 0이 되면 라우터가 패킷을 버리고 보낸 쪽에 ICMP 시간 초과(Time Exceeded) 메시지를 돌려줘요.

traceroute 는 이걸 거꾸로 이용해요. TTL 을 1, 2, 3 으로 늘려 가며 보내면 첫 번째, 두 번째, 세 번째 라우터가 차례로 시간 초과를 보내 주니 경로가 드러나요. Windows 명령은 tracert 예요.

## ARP: 같은 서브넷에서 MAC 찾기

IP 로 방향을 정해도 실제 전달은 이더넷 프레임이 하니 상대의 MAC 주소가 필요해요. ARP 가 그걸 찾아요.

1. "192.168.0.1 가진 분, MAC 알려 주세요"를 브로드캐스트(FF:FF:FF:FF:FF:FF)로 보내요.
2. 해당 IP 의 주인만 자기 MAC 을 유니캐스트로 답해요.
3. 결과를 ARP 캐시에 적어 두고 한동안 다시 묻지 않아요.

ARP 브로드캐스트는 라우터를 넘지 못해요. 그래서 목적지가 다른 서브넷이면 PC 는 목적지의 MAC 이 아니라 **기본 게이트웨이의 MAC** 을 ARP 로 찾아요.

## 핵심: IP 는 그대로, MAC 은 홉마다 바뀐다

PC(192.168.0.10)가 서버(203.0.113.5)로 보내는 과정을 따라가 볼게요. 설명을 위해 NAT 은 없다고 가정해요(NAT 은 5편에서 다뤄요).

![PC 에서 서버까지 3홉 동안 MAC 은 바뀌고 IP 는 유지되는 모습](img/net-03-routing-2.png)

PC 는 프레임의 도착 MAC 에 게이트웨이의 MAC 을 쓰고, 패킷의 도착 IP 에는 서버의 IP 를 써요. 게이트웨이는 프레임 껍데기를 벗기고 IP 를 본 뒤, 출발 MAC 을 자기 것, 도착 MAC 을 다음 라우터 것으로 한 새 프레임에 다시 싸요.

이 과정이 홉마다 반복돼요. MAC 은 "바로 옆까지", IP 는 "끝에서 끝까지"라고 외우면 돼요 ^^7

## 시험에서는 이렇게 나와요

- 네트워크관리사 2급: RIP 의 최대 홉 수, 거리 벡터와 링크 상태 구분, ARP 의 역할
- 정보통신기사: IGP 와 EGP 구분, OSPF 의 알고리즘
- CCNA: 라우팅 테이블에서 최장 일치로 경로 고르기, AD 값 비교, 정적 경로와 기본 경로

## 요약

- 라우터는 목적지 IP 를 라우팅 테이블과 비교해 다음 홉만 정해요.
- 맞는 줄이 여럿이면 프리픽스가 가장 긴 줄, 아무것도 없으면 0.0.0.0/0 이에요.
- RIP 은 홉 수, OSPF 는 비용, BGP 는 AS 사이예요. AD 는 Cisco 기준 0, 1, 20, 110, 120 이에요.
- TTL 은 홉마다 1씩 줄고, IP 는 유지되고 MAC 은 홉마다 바뀌어요.

참고로 AWS 의 라우트 테이블도 똑같이 최장 일치로 동작해요. 그 이야기는 AWS 3편 VPC 에서 이어 갈게요. 다음 네트워크 4편은 스위칭과 VLAN 이에요 (•̀ᴗ•́)و

## 확인 문제

**1.** 라우팅 테이블에 10.0.0.0/8, 10.1.0.0/16, 0.0.0.0/0 이 있어요. 목적지 10.1.2.3 인 패킷은 어느 경로를 탈까요?
① 0.0.0.0/0 ② 10.0.0.0/8 ③ 10.1.0.0/16 ④ 테이블에 먼저 적힌 경로

**2.** RIP 에서 도달 불가능으로 보는 홉 수는?
① 15 ② 16 ③ 255 ④ 제한 없음

**3.** Cisco 장비에서 같은 목적지 192.168.5.0/24 를 OSPF, RIP, 정적 경로가 모두 알려 줬어요. 테이블에 올라가는 것은?
① OSPF ② RIP ③ 정적 경로 ④ 메트릭이 가장 작은 것

**4.** PC 가 다른 서브넷의 서버로 패킷을 보낼 때 첫 프레임의 도착 MAC 주소는?
① 서버의 MAC ② 기본 게이트웨이의 MAC ③ 브로드캐스트 MAC ④ PC 자신의 MAC

**5.** traceroute 가 경로를 알아낼 때 이용하는 것은?
① TTL 이 0이 되면 돌아오는 ICMP 시간 초과 메시지 ② ARP 캐시 ③ TCP 179번 포트 ④ 서브넷 마스크

## 정답과 해설

1. **③** 세 경로 모두 맞지만 프리픽스 길이가 16으로 가장 길어요. 적힌 순서는 상관없어요.
2. **②** RIP 의 최대 홉 수는 15이고 16은 도달 불가로 처리해요.
3. **③** AD 가 작을수록 우선이에요. Cisco 기준 정적 1, OSPF 110, RIP 120 이에요. 메트릭은 같은 프로토콜 안에서만 비교해요.
4. **②** ARP 는 같은 서브넷 안에서만 통하니 PC 는 게이트웨이의 MAC 으로 보내요. 도착 IP 는 서버 그대로예요.
5. **①** TTL 을 1부터 늘려 보내면 각 홉의 라우터가 차례로 시간 초과를 돌려줘요.
