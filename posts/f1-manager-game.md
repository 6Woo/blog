## 배경: 구독 만료까지 29일, 쓸 수 있는 생성 횟수 10,000번

그누는 F1 팀의 코치가 되어 참모들과 전략을 짜는 픽셀 게임을 만들고 있어요. 픽셀 이미지 생성 서비스의 구독이 2026년 10월 16일에 끝나는 상황이었어요.

시작 시점인 9월 17일에 남은 생성 횟수가 10,000번이었어요. 29일 동안 하루 평균 약 345번을 써야 전부 쓸 수 있는 계산이었어요.

## 문제: 많이 뽑는 것보다 먼저 무엇을 만들지 정해야 했어요

생성 횟수를 무작정 쓰면 쓸모없는 그림만 쌓여요. 그래서 그누는 이미지부터 만들지 않고 설계를 먼저 확정했어요.

게임의 다섯 기둥이에요.

1. 누구를 믿을 것인가
2. 결정은 눈에 보이게
3. 불완전한 정보
4. 작은 팀의 성장
5. 완성도

## 해결: 설계 문서, 리서치, 일괄 생성 도구 순서

- 설계 문서를 먼저 쓰고 기둥과 시스템을 확정했어요.
- 취향 리서치 문서로 어떤 그림이 맞는지 기준을 잡았어요.
- 생성 요청을 목록 파일 하나로 관리하는 일괄 도구를 만들어 요청마다 비용과 결과를 장부에 남겼어요. 남은 횟수가 늘 보이니 버리는 그림을 줄일 수 있었어요.
- 완성된 코치와 F1 카 그림을 품질 기준으로 삼아 나머지를 맞췄어요.

## 중요한 설계 결정: 신뢰와 전우애를 다른 축으로

참모를 믿는 정도만으로는 부족했어요. 믿음과 정은 다른 문제였어요. 팀장이 참모들과 계속 대화하며 쌓는 전우애를 신뢰와 별개 축으로 뒀어요.

레이스에서 우승하면 업그레이드가 열리고 명성이 올라요. 명성이 오르면 본부 건물의 모습이 바뀌어요. 그림이 필요한 곳이 이 구조에서 나와요.

- 참모 초상화는 표정이 여러 개 필요해요.
- 관계 이벤트 장면과 축하 애니메이션이 필요해요.
- 명성 등급마다 본부 외관이 달라져요.

## 결과와 한계

- 설계 문서 2판, 리서치 문서, 일괄 도구, 비용 장부가 남았어요.
- 이 글을 쓰는 시점에 게임 자체는 완성이 아니에요. 그림 자산과 설계가 앞서 있어요.

## 정리

1. 한도가 있는 자원은 무엇을 만들지 정한 다음에 써요.
2. 설계가 정해지면 필요한 그림의 종류가 저절로 나와요.
3. 요청마다 비용을 장부에 남기면 남은 횟수를 늘 알 수 있어요.
