## 문제: 관리자 권한으로 돌려도 Operation not permitted

그누가 맥에서 설치 스크립트를 관리자 비밀번호로 돌렸는데 문서 폴더의 파일을 읽지 못했어요. 오류는 `Operation not permitted` 였어요. 권한이 root인데 막히는 것이 이상했어요.

## 원인: 파일 권한 위에 TCC 가 하나 더 있어요

유닉스 권한(소유자, 그룹)과 별개로 macOS에는 TCC라는 개인정보 보호 계층이 있어요. 문서 폴더나 사진 같은 위치는 어떤 앱이 접근할 수 있는지를 사용자가 시스템 설정에서 허락해요.

허락받지 않은 프로그램은 root로 돌려도 막혀요. ᕦ(ò_óˇ)ᕤ

## 사례 1: 설치 스크립트가 문서 폴더에서 막힘

관리자 비밀번호 창(osascript)으로 띄운 쉘은 root지만 문서 폴더 접근은 허락받지 않았어요. 설치용 파일이 문서 폴더 안에 있어서 복사에 실패했어요.

- 해결: 설치 스크립트가 먼저 읽을 수 있는 쪽에서 파일을 `/tmp` 로 옮겨 놓고, root 단계에서는 `/tmp` 에서 설치해요.

## 사례 2: 검색 색인 설정은 root 도 못 바꿈

복원 직후 `mdworker` 가 CPU를 250%까지 쓰는 걸 봤어요. 색인에서 개발 폴더를 빼려고 Spotlight 설정 파일을 root로 고쳐 봤지만 `Operation not permitted` 였어요. 이 파일은 TCC와 SIP가 같이 지켜요.

- 해결: 시스템 설정의 Spotlight 개인정보 보호에서 폴더를 직접 추가해요. 코드로 우회하지 않았어요.

## 결과

| | 증상 | 해결 |
|---|---|---|
| 설치 스크립트 | root 인데 문서 폴더 읽기 실패 | /tmp 로 옮겨 설치 |
| 색인 설정 | root 인데 설정 파일 쓰기 실패 | 설정 앱에서 수동 추가 |
| 부수 효과 | mdworker CPU 250% | 색인 제외 후 해소 |

## 정리

1. `Operation not permitted` 는 root여도 나와요. 권한 문제가 아니라 TCC일 수 있어요.
2. 스크립트는 문서, 데스크톱 같은 보호 폴더 밖에서 돌리게 설계해요.
3. 시스템이 막는 곳은 코드로 뚫지 말고 설정 앱에서 허락해요.
